### Added

- Community Server 0.1.0-alpha as a transport-neutral, local single-node HTTP and gRPC server over the LeanCorpus engine
- A versioned logical-index registry with opaque physical index identifiers, schema compilation, persistence and restart recovery
- Schema-authoritative document mapping, bulk indexing, refresh, search, explain, statistics and bounded inspection
- Reusable `Rowles.LeanCorpus.Server.Core`, ASP.NET Core and typed gRPC adapters, plus the `Rowles.LeanCorpus.Server.Local` reference host
- Version-one Community OpenAPI and typed protobuf contract artefacts
- Replaceable authentication, authorisation, entitlement, routing, consistency, acknowledgement, lifecycle, audit and inspection ports with permissive local defaults
- Embeddable `Rowles.LeanCorpus.Studio` workflows for health, lifecycle, inspection, documents, queries, explanations, settings and confirmed deletion
- `./devops server start`, including explicit trusted-network access with `-External`
- Integration, restart-persistence, contract, Native AOT and transport coverage for the Community surface

### Changed

- Server projects are part of the normal solution and DevOps test-suite mappings, with the reference host targeting .NET 11
- Registry writes are validated and atomically persisted; startup rejects unsupported formats, invalid names, schema mismatches and unsafe storage paths
- Bulk writes enforce configured operation, document, schema and request limits, reject invalid values, and provide bounded per-index idempotency replay
- Refresh remains an explicit visibility choice, while ordinary writes are committed by the configured local schedule
- Search validates query shape, field types, nesting, clauses, regular-expression complexity and vector dimensions before execution
- Graceful shutdown stops new operations, drains active work for a bounded period and commits owned index runtimes
- The reference host binds to loopback by default; `-External` is an explicit all-IPv4 listener for trusted networks

### Security

- Destructive index deletion requires a server-side confirmation token
- Authentication and authorisation can be replaced through dependency injection before external exposure
- Request bodies, documents, bulk operations, queries, inspection output and retained idempotency entries are bounded by configuration
- External binding does not add authentication or TLS and must be protected by the hosting environment

### Compatibility

- Community Server product version: 0.1.0-alpha and currently unreleased; alpha APIs may change before publication
- Server packages target .NET 11
- REST API: v1
- gRPC API: v1
- OpenAPI and protobuf contract artefacts are version one
- Registry format: 1
- Community topology is single-node with one shard and zero replicas
- Community does not provide clustering, replication, quorum durability, licensing, account management or external-service integration

### Added

- Immutable `CodecCatalog` and builder APIs for built-in and namespaced third-party persistent formats
- Canonical self-identifying CodecKit Frame v1 with a separate body-format version, bounded bodies and xxHash64 integrity
- Logical loose and compound file sources for common inspection, compatibility and validation
- Structured codec frame, format, checksum and corruption diagnostics
- Frame, catalogue, backwards-fixture, corruption and compound-member coverage
- Codec frame overhead BenchmarkDotNet suite

### Changed

- Current binary codec writers now use catalogue descriptors and canonical framing across direct, flush, merge and migration paths
- DocValues, stored fields, term vectors, postings, vectors, HNSW, BKD, norms, field lengths, term dictionaries and live docs use their normal current writers during migration
- Random-access formats retain bounded `IndexInput` access without ordinary-open checksum scans or whole-file materialisation
- Inspector and CLI output now distinguish frame version from body-format version and report checksum plus physical location
- Migration planning uses staged validation and coordinated rewrites for paired and compound formats
- Index compatibility includes explicit unknown-format handling

### Compatibility

- Intentionally supported 1.x and 2.x indexes remain readable and can be migrated to the canonical format
- Indexes written or migrated by 3.0 cannot be opened by 2.x; retain a verified pre-migration backup when rollback may be required
